## Why the CLI

The console is point-and-click; the CLI is the same AWS APIs from a terminal. Anything you can click, you can script, put in version control, and rerun. It's the same jump as going from clicking through an IDE's deploy dialog to a Maven command in a pipeline.

## Pick an install method

AWS now lists an **install script** as the recommended method on every OS, with the classic installers as alternatives.

| Method | Installs for | Updates with | Pick it when |
| --- | --- | --- | --- |
| Install script (recommended) | Current user by default | `aws update` | You want the simplest, AWS-verified path |
| Official installer (MSI on Windows, PKG on macOS, zip on Linux) | All users, or current user (per-user MSI on Windows) | `aws update` | You prefer a traditional installer, or your company requires one |
| Third-party package managers (Homebrew, winget, apt...) | Varies | The package manager | Not recommended here: AWS says it can't guarantee third-party repositories have the latest version |

:::note[About "pipe to shell" installs]
The install script is fetched and run in one command. That's convenient, but it means you're trusting whatever the URL serves at that moment. AWS says the script **downloads, verifies, and installs** the CLI, and the URL is AWS's own domain. If your policy forbids piping scripts, use the official installer instead.
:::

## Install

<Tabs syncKey="os">
<TabItem label="Windows">

**Install script (current user, no admin rights needed).** In PowerShell:

```powershell
irm https://awscli.amazonaws.com/v2/install.ps1 | iex
```

It installs to `%LOCALAPPDATA%\Programs\Amazon\AWSCLIV2`.

**All users instead** (run PowerShell as Administrator):

```powershell
irm 'https://awscli.amazonaws.com/v2/install.ps1' -OutFile install.ps1; try { .\install.ps1 -System } finally { Remove-Item install.ps1 }
```

**Official MSI installers** (alternative):

| Scope | Installer | Admin rights |
| --- | --- | --- |
| All users | `https://awscli.amazonaws.com/AWSCLIV2.msi` | Required |
| Current user | `https://awscli.amazonaws.com/AWSCLIV2-User.msi` | Not required |

Double-click the downloaded file, or run it with `msiexec` (add `/qn` for a silent install):

```powershell
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2-User.msi
```

</TabItem>
<TabItem label="macOS">

Supported on macOS 11 and later for current CLI versions.

**Install script (current user):**

```bash
curl -fsSL https://awscli.amazonaws.com/v2/install.sh | bash
```

It installs to `$HOME/.local/share/aws-cli` and links the command in `$HOME/.local/bin`. Make sure `$HOME/.local/bin` is on your `PATH`.

> TODO(test): confirm whether a default macOS zsh setup already has `$HOME/.local/bin` on `PATH`.

**All users instead** (installs to `/usr/local/aws-cli`, needs `sudo`):

```bash
curl -fsSL https://awscli.amazonaws.com/v2/install.sh | sudo bash -s -- --system
```

**Official PKG installer** (alternative, all users):

```bash
curl "https://awscli.amazonaws.com/AWSCLIV2.pkg" -o "AWSCLIV2.pkg"
sudo installer -pkg AWSCLIV2.pkg -target /
```

This installs to `/usr/local/aws-cli` and creates a link at `/usr/local/bin/aws`. Install logs go to `/var/log/install.log`.

</TabItem>
<TabItem label="Linux">

Supported on 64-bit recent CentOS, Fedora, Ubuntu, Amazon Linux 1/2/2023, and Linux ARM. Requires `unzip`, `glibc`, `groff`, and `less` (included in most distributions).

**Install script (current user, x86-64 and ARM):**

```bash
curl -fsSL https://awscli.amazonaws.com/v2/install.sh | bash
```

**All users instead:**

```bash
curl -fsSL https://awscli.amazonaws.com/v2/install.sh | sudo bash -s -- --system
```

**Command line installer** (lets you pin versions; x86-64 shown, use `awscli-exe-linux-aarch64.zip` on ARM):

```bash
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install
```

On Amazon Linux, remove the pre-installed yum version first: `sudo yum remove awscli`.

</TabItem>
</Tabs>

## Verify

Open a **new** terminal window (so it picks up the updated `PATH`) and run:

```bash
aws --version
```

You should see a line starting with `aws-cli/2.`. AWS's own example looks like `aws-cli/2.27.41 Python/3.11.6 Windows/10 exe/AMD64 prompt/off`; your numbers will differ.

**Version check for the rest of this guide:** walkthrough 6 relies on features from **2.22.0** onward (browser-based PKCE sign-in by default), and AWS's newer `aws login` command needs **2.32.0** or later.

## Update later

If you installed with the install script or an official installer:

```bash
aws update
```

For an all-users install, run it elevated (`sudo` on macOS/Linux, Administrator PowerShell on Windows). It keeps the install's scope (all users or current user) the same.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `aws` is not recognized / command not found | Terminal opened before install, or the install folder isn't on `PATH` | Open a new terminal; on macOS/Linux user installs, add `$HOME/.local/bin` to `PATH` |
| `aws --version` shows `aws-cli/1.x` | An old version 1 install is earlier on `PATH` | Versions 1 and 2 share the `aws` command name; see AWS's "Migration guide for the AWS CLI version 2" |
